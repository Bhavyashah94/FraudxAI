# FraudxAI US Card Transactions (100k Synthetic Benchmark)

100,000 realistic, synthetic credit card transactions across 6 modular files, generated by the open-source [FraudxAI](https://github.com/Bhavyashah94/FraudxAI) payment simulator.

**Note: This is purely synthetic data. No real cardholders, card numbers, or merchants exist in this dataset.**

| Key Metric | Value |
| :--- | :--- |
| **Total Transactions** | 100,000 rows across 6 files |
| **Master Columns** | 91 operational, telemetry, ISO 8583, and causal XAI columns |
| **Target Label** | `is_fraud`, 1,958 positive instances (**1.958%** fraud rate) |
| **Time Horizon** | 46.7 simulated days (`2024-01-01T00:01:10` to `2024-02-16T16:10:01`) |
| **Active Cardholders** | 1,000 cards across 7 Federal Reserve DCPC consumer personas |
| **Merchant Entities** | 150 merchants across authentic retail, fuel, dining, and travel MCCs |
| **Currency** | USD (denominated in dollars and minor integer cents) |
| **Storage Size** | 601.4 MB uncompressed (58.9 MB gzipped) |
| **License** | Apache-2.0 |
| **Generator Release** | `fraudx 0.3.0`, region US, seed 42, commit `e5e1813` |

---

## 1. What is this dataset?

Getting access to real credit card transaction data is notoriously difficult due to financial privacy laws. Because of this, most data science projects and machine learning benchmarks rely on:

1. **The ULB European Dataset (2013):** While widely used, all features are anonymized PCA components (`V1` through `V28`) spanning only two days of transactions, making domain feature engineering and business interpretation impossible.
2. **Basic Random Simulators:** Datasets generated by random number generators that lack real payment protocols, settlement delays, or realistic merchant categories.

FraudxAI was designed to bridge this gap. It simulates credit card transactions from real-time point-of-sale swipes through to bank settlement, giving you clear, readable columns (amounts, merchant categories, locations, risk scores, velocity counters) and realistic fraud scenarios.

---

## 2. Why is fraud set to 1.958%?

In production retail banking, fraud is rare (typically under 0.2%, or roughly 2 in every 1,000 transactions). While realistic, an unboosted 100,000-row dataset would only contain ~170 fraud cases, making it difficult to train modern gradient-boosted trees or neural networks without a massive dataset.

We enriched fraud prevalence to **1.958%** (`--fraud-rate 0.02`) so you have roughly 2,000 fraud examples to train, evaluate, and test models on without needing to download gigabytes of data.

## 3. The 6 Modular Institutional Files

Real banks do not store everything in one flat table. They separate real-time authorization feeds from delayed settlements and customer chargeback disputes. This dataset is provided both as a complete master file and as 5 modular institutional views:

| File Name | Columns | Carries `is_fraud` | GZ Size | What it represents |
| :--- | :---: | :---: | :---: | :--- |
| **`fraudxai_us_100k_seed42.csv`** | 91 | **Yes** | 47.95 MB | Master table combining all operational, telemetry, and causal ground-truth columns. |
| **`fraudxai_us_100k_seed42_auth_stream.csv`** | 25 | No | 4.67 MB | Live point-of-sale authorization feed (`MTI 0100`, STAN, RRN, Response Code, 3DS, AVS). |
| **`fraudxai_us_100k_seed42_gateway_telemetry.csv`** | 16 | No | 2.43 MB | Acquirer/Gateway risk telemetry (Client IP, ASN, Canvas hash, Geo risk score). |
| **`fraudxai_us_100k_seed42_clearing_settlement.csv`** | 13 | No | 2.37 MB | Dual-message settlement feed (`MTI 0200`) with 24-72h settlement delays and interchange. |
| **`fraudxai_us_100k_seed42_dispute_recovery.csv`** | 13 | **Yes (Label)** | 0.83 MB | Post-settlement chargeback ledger (Visa 10.4 disputes). Use this for target labels. |
| **`fraudxai_us_100k_seed42_threat_intel_graph.csv`** | 9 | No | 0.61 MB | Threat intelligence graph links (Syndicate ID, Botnet cluster, Mule ring ID). |
| **`SHA256SUMS`** | - | - | 0.01 MB | Checksum manifest for gzipped artifacts (Hugging Face). |
| **`SHA256SUMS_UNCOMPRESSED.txt`** | - | - | 0.01 MB | Checksum manifest for uncompressed CSV files (Kaggle). |
| **`dataset-cover-image.png`** | - | - | 0.02 MB | Clean static logo banner (560x280) and centered square thumbnail. |

**Important Note on Target Leakage:** `auth_stream.csv` and `gateway_telemetry.csv` represent information available at the exact millisecond of authorization. `dispute_recovery.csv` contains post-settlement chargebacks that arrive weeks later. If building an issuer fraud model, train on the pre-decision fields and use `dispute_recovery.csv` strictly as the label.

## 4. Quickstart: Train a Baseline LightGBM Model in 60 Seconds

```python
import pandas as pd
import lightgbm as lgb
from sklearn.metrics import classification_report, average_precision_score, roc_auc_score

# 1. Load the dataset (preserving zero-padded ISO 8583 and string codes)
str_cols = {
    'mti': str, 'stan': str, 'rrn': str, 'response_code': str,
    'auth_response_code': str, 'pos_entry_mode': str, 'pos_condition_code': str,
    'eci': str, 'clearing_mti': str, 'postal_code': str, 'pan_masked': str
}
df = pd.read_csv('fraudxai_us_100k_seed42.csv', dtype=str_cols)

# 2. Time-ordered train/test split (never shuffle time-series payment data!)
df = df.sort_values('tx_time_seconds').reset_index(drop=True)
split_idx = int(len(df) * 0.8)
train, test = df.iloc[:split_idx], df.iloc[split_idx:]

# 3. Select pre-decision features (drop identifiers, future post-settlement fields, and target labels)
drop_cols = [
    'transaction_id', 'card_id', 'pan_masked', 'merchant_id', 'merchant_name',
    'mid', 'tid', 'client_ip', 'device_canvas_hash', 'device_fingerprint_id',
    'is_fraud', 'scenario_tag', 'syndicate_id', 'botnet_cluster_id', 'mule_ring_id',
    'beneficiary_account_id', 'dominant_causal_driver', 'analytical_shapley_probability',
    'analytical_shapley_log_odds', 'counterfactual_input_deltas', 'counterfactual_mode',
    'counterfactual_twin', 'normative_baseline', 'explanation_narrative'
]
features = [c for c in train.columns if c not in drop_cols]

X_train, y_train = train[features].copy(), train['is_fraud']
X_test, y_test = test[features].copy(), test['is_fraud']

# Convert text/object columns to category type for LightGBM
for col in X_train.select_dtypes(include=['object']).columns:
    X_train[col] = X_train[col].astype('category')
    X_test[col] = X_test[col].astype('category')

# 4. Train LightGBM classifier
model = lgb.LGBMClassifier(n_estimators=100, learning_rate=0.05, random_state=42)
model.fit(X_train, y_train)

# 5. Evaluate on the out-of-time test set
preds_prob = model.predict_proba(X_test)[:, 1]
print(f"ROC-AUC: {roc_auc_score(y_test, preds_prob):.4f}")
print(f"PR-AUC (Average Precision): {average_precision_score(y_test, preds_prob):.4f}")
```

## 5. Comprehensive Data Dictionary (91 Columns)

| :--- | :---: | :--- |

| `card_id` | string | Card token: CARD_ + zero-padded 6-digit sequence |
| `pan_masked` | string | Masked Primary Account Number (BIN + ****** + last 4 digits) |
| `product_id` | string | Card product tier, e.g. PROD_REWARDS_SIGNATURE, PROD_CHECKING_DEBIT, PROD_TOKENIZED_DPAN |
| `cohort_id` | string | Cardholder demographic and behavioral cohort ID |
| `credit_limit` | number | Assigned credit line ceiling in major units (USD) |
| `current_balance` | number | Current ledger balance on the account in major units (USD) |
| `available_balance` | number | Available credit balance remaining in major units (USD) |

### Reproduce Exactly from Source
To regenerate this exact 100k dataset deterministically:

```bash
git clone https://github.com/Bhavyashah94/FraudxAI && cd FraudxAI
git checkout e5e1813
uv run fraudx generate \
  -n 100000 \
  --region US \
  --seed 42 \
  --days 30 \
  --fraud-rate 0.02 \
  --export-institutional-views \
  -o fraudxai_us_100k_seed42.csv
```
