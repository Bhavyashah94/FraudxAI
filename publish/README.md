**Notice: This is synthetic data. No real cardholder, PAN, or merchant appears in it.**

## 1. Overview & Core Innovations

Financial payment fraud detection in production faces two foundational crises:
1. **The Ground-Truth Explanation Void:** Real banking data warehouses record binary dispute outcomes (`is_fraud` in {0, 1}), never the true causal drivers of why an event occurred. When institutions deploy post-hoc explainers (TreeSHAP, LIME), risk teams have zero objective baseline to verify whether explanations reflect authentic fraud mechanisms or model artifacts.
2. **The Realism & Supervision Latency Gap:** Production fraud supervision is severely delayed: chargeback disputes lag by 21 to 120 days, investigator queues have finite daily triage budgets, and small-ticket fraud often goes unreported (dark fraud).

**FraudxAI resolves both gaps** by coupling continuous-time discrete-event simulation with an exact closed-form **Structural Causal Model (SCM)**:
* **Authentic Banking Plumbing:** Replicates the dual-message lifecycle separating real-time authorization (`MTI 0100` to `0110`) from delayed financial presentment (`MTI 0200` to `0210`), Automated Fuel Dispenser (AFD, MCC 5542) $175 holds, dining tip tolerances, and Address Verification Service (AVS) matrices.
* **Pearlian Causal Twins:** For every fraudulent transaction, the engine computes an exact counterfactual baseline twin:
  $$\Delta \mathbf{x} = \mathbf{x}_{\text{fraud}} - \mathbf{x}_{\text{baseline}}$$
* **Closed-Form Shapley Values:** Closed-form Owen multilinear extensions in logit space and 128-point path integration provide exact ground-truth Shapley attributions ($\phi^*$) to benchmark post-hoc explainers.
* **Anti-Separability:** Legitimate users and cybercrime syndicates share realistic telecom `/24` IP prefix pools (Comcast, AT&T) and victim-device execution, eliminating artificial synthetic separability.

## 3. Quick-Start Code

### Python / Pandas: Loading Pre-Decision Features for Machine Learning

```python
import pandas as pd

# Load pre-decision feeds available to an issuer risk switch
auth = pd.read_csv("fraudxai_us_100k_seed42_auth_stream.csv")
telemetry = pd.read_csv("fraudxai_us_100k_seed42_gateway_telemetry.csv")

# Merge strictly on transaction_id (zero target label leakage)
features = pd.merge(auth, telemetry, on="transaction_id", suffixes=("", "_tel"))

# Load the outcome label from the dispute recovery ledger
disputes = pd.read_csv("fraudxai_us_100k_seed42_dispute_recovery.csv")
labels = disputes[["transaction_id", "is_fraud"]]

dataset = pd.merge(features, labels, on="transaction_id")
print(f"Total Rows: {len(dataset):,}, Fraud Rows: {dataset['is_fraud'].sum():,} ({dataset['is_fraud'].mean()*100:.3f}%)")
```

### Baseline LightGBM Training & Evaluation

```python
import lightgbm as lgb
from sklearn.model_selection import train_test_split
from sklearn.metrics import roc_auc_score, average_precision_score

# Select feature columns (excluding identifiers)
feature_cols = [
    "amount", "available_balance", "credit_limit", "pos_entry_mode",
    "eci", "trans_status_3ds", "vaai_score", "geo_risk_score",
    "ip_distance_from_home_km", "is_cross_border", "cvv_match_flag"
]

X = dataset[feature_cols].copy()
# Convert categoricals
for col in ["pos_entry_mode", "eci", "trans_status_3ds"]:
    X[col] = X[col].astype("category")

y = dataset["is_fraud"]

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)

model = lgb.LGBMClassifier(n_estimators=100, learning_rate=0.05, random_state=42, verbose=-1)
model.fit(X_train, y_train)

preds = model.predict_proba(X_test)[:, 1]
print(f"ROC-AUC: {roc_auc_score(y_test, preds):.4f}")
print(f"PR-AUC:  {average_precision_score(y_test, preds):.4f}")
```

## 4. Technical Characteristics & Grounding Invariants

### A. Boosted Fraud Prevalence (1.958%)
Real payment card streams exhibit fraud prevalence below 0.2% (e.g. ULB credit card corpus: 0.1727%). This dataset deliberately enriches fraud to **1.958%** (`--fraud-rate 0.02`). This allows supervised machine learning models and graph neural networks to observe meaningful statistical support across all seven distinct cybercrime playbooks without requiring tens of millions of rows.

### B. Emergent 46.67-Day Simulation Horizon
The export was generated with `--days 30`, but the realized physical time span is **46.67 days** (`2024-01-01T00:01:10` to `2024-02-16T16:10:01`). This divergence is arithmetic and physically grounded:
$$N = \text{density} \times T, \quad \text{where } \text{density} = \text{per-card rate} \times \text{active cards}$$
When cybercrime attacks strike cards, cardholders exhibit cohort vigilance (`spec/02`) and freeze compromised cards within hours. In this 100k batch, fraud strikes 720 of the 1,000 cards and freezes 533 of them. With only 68% of the card pool generating legitimate transactions, producing 100,000 rows takes 46.67 days at the spec-grounded per-card rates.

### C. Zero Label Leakage Architecture
* `auth_stream.csv` and `gateway_telemetry.csv` contain strictly pre-decision fields available before issuer scoring.
* `dispute_recovery.csv` contains post-settlement chargeback records (`MTI 0200` dispute arrival). **Do not join `dispute_recovery.csv` into inference feature stores**, as it represents downstream operational supervisory ground truth.
